# Signoff manifests

- `sg13g2-serdes.json` — block manifest: `kind: "mixed-signal"`, evidence map.
  `partition_boundary` is declared from `spec/decisions/DR-008-stage-boundaries.md`
  (the spec itself, issue #2, is still PROPOSED, so re-check on ratification).
  Evidence `2.digital` is the routed digital GDS attestation
  (`evidence/item2.json`, made with `klt signoff --attest 2`, which klt 0.8.0 —
  the pin at the time — lacks; it was produced with a throwaway klt 0.9.1 and
  graded by that pinned 0.8.0). That is a historical note about how item 2 was
  graded, not the current pin: the pin is now 0.9.0, see below.
  Evidence `2.analog` is the analog top GDS attestation (`evidence/item2.analog-top.json`, issue #113).
- `design-evidence-tiers.md` — vendored verbatim from
  `2AMLogic/klayout-tools` `docs/design-evidence-tiers.md` at tag `v0.8.0`,
  commit `c572046be644e0407f693f2410f3abb799d68a3a`. That tag is **verified**
  (2026-11-14): this file is byte-identical to upstream's copy at `v0.8.0`
  (sha256 `a26b9026…`), which is also the hash the verdict grades against
  (`source_doc_content_hash` in `sg13g2-serdes.signoff.json`). It has **not**
  been re-vendored for the 0.9.0 pin — upstream's `v0.9.0` copy differs
  (sha256 `08dcbfd2…`) — so the tiers text behind the current verdict is still
  v0.8.0's.
- `sg13g2-serdes.signoff.json` — verdict of record, generated by
  `klt signoff`; CI regenerates it and fails on any difference.

The klt version is pinned in two places, `scripts/klt-pin.env` (CI gate, the
authority) and `klt_install` in `layout/toolchain.json` (layout/sim flows) —
both read `0.9.0` as of this writing;
`scripts/check-ci.sh json` fails if they disagree. Bumping it means
regenerating the verdict (it embeds `build.*`) and re-vendoring the tiers doc.
Regenerate with `scripts/check-ci.sh --regen`: it re-attests items 1, 9 and 10,
refreshes each of their `evidence[<id>].content_hash` pins from the re-attested
envelope's own `provenance.input.content_hash` (the field the grader
hash_checks — not always the sha256 of the envelope's `source`), and only then
regenerates the verdict, which is graded from those pins. Item 1 re-attestation
runs the netlist and synthesis freshness commands `design/inventory.item1.json`
declares, so `--regen` needs a provisioned tree (`scripts/setup-env.sh`, then
`source scripts/env.sh`); `scripts/check-ci.sh signoff` does not — it carries
those `local_only` results from the committed envelope.
